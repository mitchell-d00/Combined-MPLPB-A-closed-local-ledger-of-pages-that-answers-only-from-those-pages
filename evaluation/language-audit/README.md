## Evidence-based taxonomy

The principal limit is interpretation: situation-to-relation mapping, free-form procedures, thresholds and applicability, comparative questions and unrecognized disposition relations. Body extraction additionally encounters unresolved pronouns (powders / `it`) and missing requested quantities. Retrieval/eligibility is a contributing limit for h15. Compatible source ownership causes h10's ambiguity. The contradiction reproductions expose a separate implementation defect: negative evidence was discarded before conflict assessment; positive evidence then rendered as supported. Legacy statement and practical paths also overblocked different denied values.

These classes overlap. Source bodies and individual repairs in CASES.md are the evidence; headings, document identity and lexical overlap are not support. No new evidence for unrestricted cross-sentence resolution, cross-page joins, general aliases, exceptions, ordered procedure inference, multipart completion, or unrestricted conversational recovery was established by this patch.

## Rules implemented

* A bounded assertion contains subject, relation, value, polarity, exact qualification, source ID/hash/path, and verbatim quote. The selected request frame supplies subject/relation; an eligible body extractor must supply the value. The original user question remains in the answer object. This is an enforced comparison contract for strict statement/literal extensions, **not** a replacement for all conversation/assisted/procedure representations.
* Graph predicate denials now retain negative spans, including `do not/never store/keep`, `is/are/was/were/should/must not`, and `does not contain`, only when the corresponding complete positive sentence matches a declared relation. No general negation rewriting, quotation removal, synonym inference or inference from headings is licensed.
* Direct contradictions require the same subject, relation, value and qualification. A denial of another value does not contradict the supported value. Same-page and cross-page evidence use the shared aggregator. Graph nodes expose polarity. Literal and practical extractors retain negative quotes even when they also find positive evidence. Existing policy-denial semantics remain conservative.
* Relevant prefixed `if/when/unless` and year-scoped denials whose applicability cannot be resolved block an unconditional return; unresolved quotes remain inspectable. Different dates in due/scheduled value positions remain different assertions. No date arithmetic or implicit historical supersession is inferred. Ledger revisions and withdrawals alone decide eligibility; historical source text is not silently erased.
* Storage questions accept keep/store and passive stored/kept; source instructions additionally accept `ENTITY should/must be stored/kept in VALUE`. Code-purpose questions additionally accept `What is the purpose of code CODE?`. Unknown names are opaque entities. Full source sentences preserve recommendations versus requirements. Request qualifiers outside these grammars abstain; passive assertions do not manufacture current physical location.
* Multiple eligible supporting pages remain ambiguous, including identical claims and shared ancestry. There is no ownership contract change. Provenance, collection scope, sealed capture manifests, delivery restrictions, ancestry and source-state rechecks remain authoritative.

Positive-only evidence returns a verbatim source claim, negative-only evidence cannot supply an affirmative answer, applicable disagreement blocks support, unresolved scope abstains, and unknown language remains unsupported. Candidate diagnostics expose positive, negative and unresolved quotes for inspection. Users can use existing collection selection, source inspection, clarification and revision routes; a declaration or interpretation correction never writes ledger facts.

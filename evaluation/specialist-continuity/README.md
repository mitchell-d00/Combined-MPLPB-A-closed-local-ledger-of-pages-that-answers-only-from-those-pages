# Specialist continuity implementation: 2026-10-31

Implementation: native `mplpb_work`, standard-library SQLite, capability-gated
records and immutable events. See the [operation guide](../../docs/SPECIALIST_CONTINUITY_API.md)
and [relationship to the supplied papers](../../docs/SPECIALIST_CONTINUITY.md).

`demo.json` is generated by:

```sh
python -m tools.demo_specialist_continuity --output evaluation/specialist-continuity/demo.json
```

It records an offline developer fixture with five distinct instance identities
and role-scoped capabilities. A new subprocess replaces the ended implementer and
recovers the live challenge and failed attempt. A reviewer revises the claim,
resolves its challenge with pinned source evidence, and a changed experiment
produces a passing receipt. The task then completes; the original inferred premise,
failed route and authorship history remain. The ended writer is rejected.

The fixture exercises the coordinator; it does not call five AI models or measure
real research productivity, consciousness, independent corroboration, information
gain or general truth. Random credentials, IDs and timestamps are not scored.
Code hashes identify the implementation used. No raw capabilities or database are
published in this report.

Development checks cover:

- Separate model/instance/seat identity; fresh-process handoff and fencing.
- Expiry, revocation, operation/task/tool allowlists and host-only administration.
- Live and historical visibility, profile filtering, explicit transfer and blocked
  reference laundering; dedicated HTTP mode closes ordinary source-reader routes.
- Source body-span pins, current provenance eligibility, retained stale evidence,
  transitive invalidation, challenge resolution and receipt-backed acceptance.
- Failed-route relationships, explicit changed retries, unknown execution results,
  no automatic re-execution and host reconciliation.
- Review roots versus span novelty, copied-review provenance and bounded rounds.
- Concurrent thread/process writers, stale compare-and-swap rejection, event-chain
  corruption and independently anchored truncation detection.
- CLI integration and the local authenticated HTTP path.

Run the suite with `python -m unittest tests.test_specialist_continuity -q`.
Validation: the full **716-test** Python suite passes. A final **50-test**
continuity/local-UI run verifies the dedicated host-route hardening; the
**51-test** answer/continuity integration run passes as well. UI script, browser
transport, JavaScript API and fixture crawler checks pass. A wheel built without
network dependencies passes module-byte parity and CLI/bootstrap/write/handoff
checks outside the checkout. Exact pins and scope are in `validation.json`.
WebAssembly and Chromium release checks remain for the new PR head in CI.
The existing pottery answer coverage stays 3/32, 2/19 and 1/8, with no observed
wrong returns; work-state assessments do not enter the strict answer engine.

These inspected fixtures are development evidence. Sealed multi-provider trials,
provider/OS isolation, a hosted browser work UI and quantitative Watcher stopping

not a sandbox for a process holding unrestricted database/filesystem access.

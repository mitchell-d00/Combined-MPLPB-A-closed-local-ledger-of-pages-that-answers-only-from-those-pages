# Hermes-02 namespace-bound receipt I/O

Last reviewed: 2026-11-28.

The unchanged Heka worker is the comparator. Each draw drives two disposable
host-owned Git repositories and distinct persistent reservation directories.
Both fixtures have the same ref name and Git object IDs, and share an unchanged
eligible ledger and question. The host retains normal scoped grant handling.
A known completed reservation stays confined to its own directory.

The test seam is a temporary Node module load hook limited to the hash-pinned
Heka bridge. It may substitute the binding operand immediately before that
worker's existing digest comparison. No other worker code changes. A local
control mints a binding normally. The foreign contrast takes the exact binding
from the other worker's successful trace. The mutation contrast changes its
namespace alone. A restart repeat presents the original binding in its own
namespace, in a fresh process. Missing and revoked authority are tested with
valid local bindings. A foreign binding is also exercised with missing
authority. This seam is only a lab driver and is not a production receipt API.

Freeze the operator generator, development and fresh packet digests and held
keys, and the exact scorer before executing. No randomness is used. Test the
unchanged comparison first. If it passes, select it without a repair and pin
that decision before opening the fresh operator input. Each draw has nine
ordered phases. Fresh switches donor and peer, changes the report layout,
actors and order of contrasts, and repeats the same causal mechanisms.

Require a complete proof from the actual reader in every phase. Compare exact
source, question, claim, snapshot, action, ref, old and new IDs and namespace
against the observed binding. A foreign or mutated binding must differ in the
namespace alone, be refused before controller admission and never reach Git.
Record initial admission and final controller decisions separately. Missing
and revoked authority never reach the writer. The authorized local controls
must each make one intended Git write with an independently verified ref and
marker, and a durable completion. Refusals must leave both repositories and
reservation records byte-identical. Each repeat uses a new worker process;
a rejection cannot consume B's future legitimate request. Record both
namespaces and both readbacks after every phase. Retain failures as observed.

One operator prepared both packets and scores. Held keys stay off the worker
command line and outside Git. The host is trusted. The experiment does not
demonstrate authentication, malicious-host resistance, alias equivalence,
distributed locking or cross-resource atomicity. Production dispatch is
outside the study.

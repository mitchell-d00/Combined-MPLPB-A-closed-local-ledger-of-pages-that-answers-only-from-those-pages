## Canonical projection and effect

Use native Strict Ask under the exact original question and internal profile.
Use default passage budgets and the existing 200,000-character, 1,000-unit
and eight-record scan limits. Native process timeout is six seconds.
Require one checked, affirmative, source-attributed instruction and exact
heading/byline and directive coordinates in current intact eligible
originals. Preserve native proposition and citations, role layers,
modality, conditions, date obligation, missing text, original question
and revision snapshot. Complete requires a checked date. Partial requires
the explicit unresolved instruction date. Canonical
`instruction-source-assertion-v1` is UTF-8 JSON, recursively sorted object
keys, compact separators, one final newline and unchanged array order.
Its `status` is `source_assertion`, with `truth` and `execution` set to
`unverified`. It carries no fixture labels or evaluator fields.

Build the intended commit from actual projected bytes in `assertion.json`.
The host grant binds the record digest, native proof digest, source
revision/eligibility snapshot digest, reader pin, action, repository
identity/path, namespace, ref, old/new object IDs, and policy version/digest.
Host direction supplies that grant independently of source text. Reuse
Heka's final reread before fixed controller CAS and its original controller
and reservation store. Independently verify the ref, marker and canonical
record, then separately inspect the durable outcome. No production transport
is configured. [Pinned dependencies](DEPENDENCY-SHA256SUMS).

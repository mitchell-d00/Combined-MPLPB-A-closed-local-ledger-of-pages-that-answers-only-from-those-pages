# Seshat, Anubis and Horus frozen language batch

Last reviewed: 2026-11-27.

Released baseline `a442c8f0c9629b65a3af38ba57319aa9c2af8dbe`.
The bounded order is Seshat, then Anubis, then Horus. Each set has six
development executions and six fresh executions per reader. Each arm has
three supported targets and three matched contrasts. Counts are reported by
distinct question string and by executed case. The fresh inputs and keys are
prepared by the implementer and held separately until the candidate is
pinned. Independent preparation/blinding and assessment are NOT_RUN.

| Set | Retained diagnostic | Narrow interpretation hypothesis | Constraint |
|---|---|---|---|
| Seshat | C3-REPL-P02 and X01/X03 report questions omit the object, which the existing report query parser expects. The source bodies already name recorder, reporter and embedded writer. | Admit bounded object requests to the existing report verifier. | Require one documentary answer. Recorder and reporter are separate. Preserve complete quotations, identity and eligibility. |
| Anubis | Thoth left negated wording outside its location rule. Existing reported-content logic distinguishes outer denial from inner denial, but ordinary explicit yes/no report phrasing has limited interpretation. | Bind outer and embedded polarity in a whole-question report proposal. | Match both polarities exactly for those question forms. Missing evidence is a refusal and cannot prove the negative. |
| Horus | C3-REPL-P03 and X04–X06 expected bounded conditional instructions. The ordinary instruction parser rejects an “if” phrase inside an argument slot. | Bind the condition separately and verify it in the existing named modality checker. Extend a bounded condition question to the existing permission proof. | Exact governing condition, selected modality and unchanged source authority. Permission or intention supplies no evidence of execution. |

Development and fresh are sealed with exact inputs, questions, budgets,
expected source dispositions, proposition fields and witness coordinates.
Both readers use the unchanged Cryptid v5 runner in Linux Bubblewrap.
The scorer keeps keys outside worker access and public artifacts. A complete
answer needs exact eligible witnesses and the expected source-scoped claims.
A useful partial needs supported claims and an explicit missing obligation.
Wrong roles, polarity, conditions or witnesses are unsupported claims.
An empty supported label, failed execution and a proper refusal have different
statuses. This batch expects no partial answer on the authored single requests.

Select a release candidate only if frozen fresh gains coexist with zero
unsupported claims and no protected losses. Run the 52-case capability gate,
832 public contracts, BB and the retained protected reader outcomes as well
as exact-head software checks. Changed previously missing consumed cases are
coverage evidence if scored separately. Stop after all three frozen fresh
arms, with no repair between them. Preserve first results, failed runs and
remaining misses. Original 17 private checks stay incomplete, 100 held cases
NOT_RUN, and publication-history exposure remains open outside this work.

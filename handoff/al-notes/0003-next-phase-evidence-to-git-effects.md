## 4. Matched cases and observations

Freeze small development and fresh packets with new IDs. Fresh is opened only
after the bridge candidate is pinned. Preparation/scoring and key access must
be disclosed; a held file is not automatically independent or blinded.

Include these contrasting structures:

- Complete eligible reader proof plus exact host grant: one intended Git update.
- Correct printed-writer selection but wrong reporter: no dispatch.
- Duplicate eligible documents, withdrawn source, or missing proof: no dispatch.
- Complete source proof with missing/revoked authority, or only an Al-note
  instruction: no dispatch.
- A changed source or lost eligibility at the declared between-check hook:
  require the frozen freshness response rather than reusing stale proof.
- A receipt/proposal for the wrong action or target revision: no dispatch.
- A competing Git writer: retain its ref/marker; admission and failed CAS are
  separate observations when evidence and authority still satisfy policy.
- Restart after completion or known failure: no duplicate dispatch. Interruption
  after Git before durable completion remains indeterminate without blind retry.

Record each stage's actual output and source/effect identities, writer attempts,
successful updates, ref/marker readback and durable outcome. Missing execution,
unsupported evidence, denied authority, failed effects and indeterminate
completion are different results. A claim-free answer is not automatically the
correct frozen status. A successful Git readback does not invent a completion
receipt.

Run the unchanged baseline first and preserve any unconnected interface as such.
The adapter is a separate lab candidate. Preserve first failures, first fresh
scores and any infrastructure failures. Do not repair against fresh and continue
calling it fresh. Do not claim more passed cases or an end-to-end guarantee than
the frozen trace actually demonstrates.

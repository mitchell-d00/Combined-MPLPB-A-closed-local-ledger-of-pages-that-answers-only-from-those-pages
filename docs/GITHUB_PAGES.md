# Open MPLPB at a web address

The `Publish MPLPB browser runtime` workflow builds the standalone runtime and
publishes it as the GitHub Pages site's `index.html`. Visitors need a current
browser with the required WebAssembly/storage features, not a Python process.

Expected project address:
https://mitchell-d00.github.io/Combined-MPLPB-A-closed-local-ledger-of-pages-that-answers-only-from-those-pages/

In repository Settings → Pages → Build and deployment, the Source must be
**GitHub Actions**. The workflow cannot create or administer Pages with its ordinary
GITHUB_TOKEN. If Pages is still configured to publish the branch root, that root
contains the desktop entry point and does not run the standalone runtime.

The workflow tests Python, UI/transport logic and actual WebAssembly execution,
verifies the pinned upstream core archive, then uploads only `dist/`. User save
files and the rest of the repository are not the deployed site. The artifact's
`index.html` embeds the engine, pages and runtime. Generated bytes remain outside
Git. The root repository `index.html` retains desktop launcher behavior.

Sessions and imported captures stay in each visitor's browser, separate from the
repository and from other visitors. No server language model or Python service is
started. Explicit Wikipedia search/import still needs network/CORS access. See
[BROWSER_RUNTIME.md](BROWSER_RUNTIME.md) for runtime limits and storage behavior.

Walk back: revert the workflow commit or re-run a previously successful deployment.
An older runtime can reject captures pinned to newer adapter bytes. Export important
transcripts before reverting. Browser saves are not erased by a deployment.

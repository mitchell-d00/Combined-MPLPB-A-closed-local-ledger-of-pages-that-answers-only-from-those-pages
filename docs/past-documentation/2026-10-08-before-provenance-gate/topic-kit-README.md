# Six-topic HTML test kit

Thirty new ledger pages: five each for RPG history, fossils, animals, dinosaurs,
OpenAI history, and computing history. Each topic has fifteen frozen probes.
The existing Combined MPLPB reader is unchanged.

Open `evaluation/topics/index.html` in a browser to inspect recorded outcomes,
page bodies, scope fields, sources, candidates, normalized terms, exclusions,
and profile comparisons. Each corpus also has its own browsable `index.html`.
The report works offline; custom questions need the local Python query bench.

From the repository or extracted kit root:

```sh
python3 tools/test_topic_examples.py --serve
# Open http://127.0.0.1:8765
```

The server binds to loopback only. Questions call the original Python `answer`
function, not a JavaScript approximation. No model, network retrieval, database,
or package installation is required. Source links are optional external reads;
they do not participate in answering.

To use the normal command line:

```sh
python3 -m mplpb_combined ask examples/topics/rpg-history "what is percentile" --why
python3 -m mplpb_combined ask examples/topics/fossils "groundwater" --why
python3 -m mplpb_combined ask examples/topics/fossils "groundwater" --no-prose --why
python3 -m mplpb_combined ask examples/topics/openai-history "openai chatgpt launch 2022" --why
python3 -m mplpb_combined validate examples/topics/dinosaurs --strict
```

Refusals use the original exit codes: ambiguous is 2; not in corpus is 3.

## Reproduce

```sh
python3 tools/build_topic_examples.py --check
python3 tools/test_topic_examples.py
python3 -m mplpb_combined.evaluate evaluation/topics/manifest.json --out evaluation/topics/results.json
```

`spec.json` contains the page declarations, prose, source URLs, questions, and
desired labels. `corpus-lock.json` pins the specification bytes and semantic
page hashes. `manifest.json` pins the probe bytes. The report runner rejects
changed or invalid corpus records before evaluation. `trace-results.json`
contains every original reader result for four profiles. `results.json`
contains the existing evaluator's ledger and lexical baseline scores.

The builder uses fixed IDs, timestamps, and writing order. It checks all
existing generated bytes before writing and refuses to overwrite edited
fixtures. To create a different corpus, use a separate directory and manifest
rather than silently changing this frozen test set. Newly created fixture
directories can be generated with `python3 tools/build_topic_examples.py`.

## What is being tested

Each topic repeats the same controlled categories:

| Category | Probes per topic | Desired outcome |
| --- | ---: | --- |
| Exact declared scope | 5 | Return the specified page |
| Unique prose term | 1 | Return the specified page |
| Shared scope word | 1 | Ambiguous |
| Shared prose term | 1 | Ambiguous |
| Answerable paraphrase | 1 | Return the specified page |
| Unsupported budget intent | 1 | Not in corpus |
| Explicit `not-for` exclusion | 1 | Not in corpus |
| Absent subject | 1 | Not in corpus |
| Comparison absent from any single page | 1 | Not in corpus |
| Unsupported negative premise | 1 | Not in corpus |
| Stopword-only question | 1 | Not in corpus |

The labels represent desired page-grounded outcomes, not predictions copied
from the reader. The paraphrase label remains a return when the reader refuses.
An unsupported budget or negative premise remains a refusal when the reader
returns an on-topic page. Return evidence is a verbatim span; it does not make
the labels independently adjudicated.

First run: each topic has 12/15 correct desired outcomes, two wrong returns,
and one wrong refusal. Aggregate: 72/90 correct, 12 wrong returns, six wrong
refusals. All six paraphrases are refused. All twelve unsupported budget and
negative-premise questions return the first page. The repeated construction
explains the identical counts; these are mechanism demonstrations, not a
population estimate. See the full per-probe and baseline records in the report.

## Provenance and limits

Codex authored the corpus, questions, and labels together, with no independent
review. Fields, prose, questions, and labels were frozen before execution and
were not tuned after results. One broken museum source URL was corrected
after the initial run; the corpus bytes and labels were unchanged.

Every page declares `origin=machine`, depth 1, and no ratification. The internal
profile serves these pages. The external profile withholds them; a withheld
record appears in the trace. No machine-authored material is marked human.

These are small educational summaries of selected events and concepts, not
comprehensive reference works. Source URLs document background for the
paraphrases; sources are not part of the ledger bodies. The reader is lexical,
uses its original stopwords and suffix stripper, drops strictly less-specific
scope owners, and never synthesizes an answer across pages.

Corpus validation reports zero errors and warnings. The original 122 tests
pass. Local API checks cover query profiles, exclusion behavior, prose
fallback, ambiguity, page routes, and path containment. JavaScript syntax is
checked. Browser visual testing was unavailable in the build environment.

For independent evaluation, follow `evaluation/README.md` in the upstream
repository: separate corpus and question authors, blinded labels, frozen
inputs, and untouched final-test questions. These fixtures alone do not show
generalization to real users or independently authored corpora.

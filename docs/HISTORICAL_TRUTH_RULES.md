# Historical review and synthetic truth entry rules

Last reviewed: 2026-11-17.

Package role: [how this part fits Combined MPLPB](PACKAGE_GUIDE.md#documentary-research). This guide covers documentary inspection; source assertions, candidate relations and historical truth remain distinct.

Historical truth cannot be established by accepting JSON, counting agreeing models, matching quotations or passing tests. This implementation records scoped review decisions and separately tests the entry method in a known synthetic universe. It never sets real `historical_truth_independently_verified` to true.

Entries use the existing WorkStore claim/evidence/review records, capability credentials, append-only history, explicit visibility and pinned revisions. The new closed API methods are `historical_review` with an `entry` and `historical_reviews` with a `claim_id`. They are available through the existing `python -m mplpb_answers work request ... --credential-file ... --input ...` interface. No new source-authority bypass or ledger correction operation is introduced.

An entry requires a visible current claim/revision; nonempty currently eligible source-evidence references; an identified reviewer label and declared kind (`synthetic_fixture` or `human_declared`); support/challenge/inconclusive decision; rationale; exact review scope; independence attestation; and explicit uncertainties. The entry is appended as an existing review with `regime:historical-review-v1`. Actor capability seat, claim digest and evidence revision pins are generated by the adapter, not trusted from the submitted entry. Existing write rights and visibility determine whether it can be recorded.

Inspection rechecks current evidence and claim state and performs a final work/source view comparison. Changed, restricted, withdrawn or corrupted dependencies require recheck. A challenge remains contested; a later review never silently rewrites an original historical record. Two reviewer names on one capability seat are not two independent reviewers. Host-issued capabilities authenticate authorization, not that a reviewer is a real independent human. Self-declared human identity and independence remain explicitly unauthenticated.

```sh
python -m tools.demo_historical_review --output NEW_SYNTHETIC_DIRECTORY
python -m unittest tests.test_historical_review_rules -v
python -m tools.historical_targets --output NEW_TARGET_PROTOCOL_JSON
```

The demo creates ordinary fictional source prose, a proposed claim, two clearly labelled **software fixture** review entries and a separately hash-pinned synthetic oracle. It does not use real historical originals, insert hidden answers into sources or fabricate human reviewers. The oracle must name a `synthetic-` universe, match the exact proposition, carry a Boolean test truth value and match its supplied digest. Matching fixture decisions yield only `synthetic_fixture_truth_matches:true`. A wrong oracle value, wrong proposition, duplicate reviewer seat or stale source fails the corresponding check. This is a test subject for the method, not historical accuracy evidence. Oracle hashes provide binding, not independent authority.

Real historical review requires independently accountable people, full source context, counterevidence, scoped adjudication and institutional/custodian verification of reviewer independence outside this software. Even agreed human interpretations are distinct from independently established historical truth. The software preserves these distinctions rather than inventing a universal truth certificate.

The prospective evaluation reuses the existing sealed-study sandbox and `tools.unprepared_challenge` packets/review/adjudication validator. Freeze implementation/source hashes/budgets first, obtain at least 200 independently authored unseen questions across at least three domains, seal private answerability/expected annotations outside runtime, preserve every output, then unseal only for review/scoring. `tools.historical_targets` requires validated review submissions and annotations matching a custody digest before reporting rates; it never authenticates reviewers or labels development questions unseen. Unknown metrics remain null. Wilson intervals and zero-observed-error upper bounds report finite-sample uncertainty; relationships clustered by case/domain need additional statistical analysis. Current eligible citation rates require a separate final source-state audit and are not inferred from human citation checks.

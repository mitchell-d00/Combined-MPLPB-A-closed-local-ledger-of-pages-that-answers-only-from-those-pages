This area holds proposed capabilities, reader experiments, candidate repairs
and research. Use the [MPLPB guide](MPLPB.md) for the released user path.
An experiment's success establishes its measured cases, not general reading
ability. A branch candidate is not released merely because its report exists.

Scope: proposed or tested experimental capabilities. Use each pinned report's
revision and [the current handoff](../HANDOFF.md) to continue work; the
[history index](DEVELOPMENT_HISTORY.md) distinguishes earlier contracts.

## How a repair becomes usable

Reproduce a failure on the current reader, freeze contrasting examples, retain
the baseline, and repair the common operation. Preserve existing valid support,
qualifications, source state and citations. Freeze the candidate before opening
fresh transfer material. Once transfer failures guide a repair, that material is
development evidence. Same-operator testing is labelled accordingly.

Required software checks and the normal protected release workflow still apply.
Detailed pins, scores, custody and unresolved misses remain in linked technical
reports and the [handoff](../HANDOFF.md). The [Test Index](TEST_INDEX.md) is the
authoritative inventory; this page does not maintain a second scorecard.

Reader owns verification rules, Intake and Research owns source proposals, and
Applications owns experimental interfaces. Their [department pages](departments/README.md)
retain commands and implementation paths. No physical file migration is part of
this navigation change.
